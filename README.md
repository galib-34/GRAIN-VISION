# GRAIN-VISION — AI Rice Quality Assessment & Procurement PWA

GRAIN-VISION is a mobile-first Progressive Web Application (PWA) and robust Python FastAPI backend designed for agricultural field procurement officers, millers, and farmers. It assesses rice grain quality from mobile camera captures using an ultralytics YOLOv8n object detection model (`backend/models/train2.pt`), estimates quality-adjusted procurement valuations, and manages seller records.

---

## ⚠️ Important Real-World Disclaimers

> **Estimate for Procurement Decision Support:**
> All calculated **Quality Scores**, **Priority Schedules**, and **Estimated Pricing** outputs generated by GRAIN-VISION are advisory decision-support metrics derived strictly from computer vision defect detection. They do **NOT** constitute an officially accredited statutory grade or legal guarantee.

> **Informational Baseline Notice:**
> The daily Mandi modal reference price (sourced from AGMARKNET via the Government of India Open Government Data platform) is an informational market indicator and does **NOT** constitute a formal, binding purchase offer for any specific rice lot quality.

## Key Architectural Highlights

1. **Robust Mandi Pricing Engine (`backend/app/pricing.py`)**:
   - **Background Scheduled Caching:** Schedulers refresh daily mandi price benchmarks in the background (every 12 hours) asynchronously.
   - **Zero Inference Blocking:** Individual grain image analysis operations **never** trigger live external HTTP requests, eliminating network lag during field assessments.
   - **Graceful Fallback & Diagnostics:** If `data.gov.in` encounters an HTTP 403 or network failure, detailed diagnostic stack traces are logged internally. The engine falls back seamlessly to the last cached price, a manual reference, or a configured regional baseline price (`BASE_REFERENCE_PRICE_PER_QUINTAL`). Service failures are never disguised under an "unconfigured" label.

2. **Dynamic Routing & Safe CORS**:
   - Environment variables are loaded at the absolute entry point of `backend/app/main.py`.
   - Wildcard CORS (`*`) is strictly disallowed in production mode (`ENVIRONMENT=production`).
   - The frontend (`frontend/app.js`) features dynamic environment resolution without hardcoding `127.0.0.1` or `localhost`, allowing mobile devices on local networks or secure HTTPS hosted domains to connect effortlessly.

3. **High-Density Grain & Low-Bandwidth Optimizations**:
   - **Client-Side Canvas Compression:** High-resolution mobile camera captures (12MP–48MP / 15MB+) are compressed on an HTML5 canvas prior to upload (~300 KB JPEG), preventing network timeouts over rural 3G/4G connections.
   - **Backend Memory Safeguards:** High-density images containing hundreds of grains are safely bounded (1920px max dimension) and evaluated with PyTorch inference mode without memory leaks.

4. **Phase 1 Core Foundations**:
   - **User Authentication:** Multi-user sessions with PBKDF2-HMAC-SHA256 password hashing.
   - **Dashboard Hub:** Real-time visibility into Total Assessed Lots, Accepted Lots, Rejected Lots, and Total Procured Value (₹).
   - **Seller Management:** Farmer profile creation and persistence for streamlined lot intake.
   - **Lot Weight Entry:** Native numeric touch keypad input (`kg` or `quintal`).
   - **Explainable Pricing:** Transparent line-item breakdown of base mandi rates, defect-based quality adjustments, and total lot payouts.
   - **Accept/Reject Determination:** Interactive procurement decision logging with rejection reason tracking.

## Quickstart & Execution Guide

### Prerequisites
- Python 3.10 or newer (universal `python` commands used throughout).
- Modern web browser (Chrome, Safari, Edge, or Firefox on mobile or desktop).

### 1. Backend Setup

Open a terminal in the `backend/` directory:

```bash
# Create virtual environment
python -m venv .venv

# Activate virtual environment
# Windows (PowerShell):
.\.venv\Scripts\Activate.ps1
# Linux / macOS:
source .venv/bin/activate

# Upgrade pip and install dependencies
python -m pip install --upgrade pip
pip install -r requirements.txt

# Configure environment variables
# Copy template if .env does not exist:
copy .env.example .env
```

#### Running the Backend:

- **Development Mode:**
  ```bash
  python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
  ```

- **Production Mode (Standard Multi-Worker Execution):**
  ```bash
  python run_production.py
  ```
  *(Or via Gunicorn on Linux hosts: `gunicorn -c gunicorn_conf.py app.main:app`)*

The API is accessible at `http://localhost:8000`, interactive OpenAPI documentation at `/docs`, and health diagnostics at `/api/health`.

### 2. Frontend PWA Setup

In a second terminal, open the `frontend/` directory and serve the static files:

```bash
python -m http.server 5500
```

Open `http://localhost:5500` on your workstation, or open `http://<YOUR_LOCAL_IP>:5500` from a smartphone connected to the same Wi-Fi network.

Default demo officer credentials:
- **Username:** `officer`
- **Password:** `grainvision2026`

## Mobile Camera Integration (Section 3)

The application binds directly to smartphone camera hardware using HTML5 `capture="camera"` and `accept="image/*"` attributes:

- **Direct Camera Snap:** Clicking **📸 Snap Grain Sample** triggers the native smartphone camera viewfinder.
- **Gallery Upload:** Clicking **📁 Choose Photo** opens the device photo library for pre-captured images.
- **Client-Side Canvas Optimization:** Automatically downscales and compresses camera images to ~1600px max dimension before transmission.

## Defect Classes & Procurement Priority

The trained YOLOv8n model detects 8 grain classes:
1. `sound` (Intact healthy grain)
2. `whole-chalky` (Full grain with chalky opacity)
3. `broken-clear` (Broken translucent grain)
4. `broken-chalky` (Broken chalky grain)
5. `unsound` (Damaged, discolored, or diseased grain)
6. `foreign-object` (Organic debris/husk)
7. `stone` (Mineral contaminant)
8. `plastic` (Inorganic contaminant)

Priority ordering can be adjusted via `GRAIN_CLASS_PRIORITY` in `backend/.env`.

## Production Deployment & Reverse Proxy Guide

In production, terminate TLS/HTTPS using a reverse proxy such as Caddy or Nginx:

### Caddyfile Example:
```caddy
grainvision.example.com {
    # Reverse proxy backend API
    handle /api/* {
        reverse_proxy localhost:8000
    }

    # Serve static frontend PWA
    handle {
        root * /var/www/grain-vision/frontend
        file_server
        try_files {path} /index.html
    }
}
```

When deployed behind a reverse proxy, set `ENVIRONMENT=production` and `CORS_ORIGINS=https://grainvision.example.com` in `backend/.env`.
